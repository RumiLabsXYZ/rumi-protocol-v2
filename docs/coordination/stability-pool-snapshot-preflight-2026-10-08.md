# Stability Pool exact-Wasm capture proposal

The installed Stability Pool Wasm has no matching copy in the project's retained local build artifacts. To validate its behavior against a proposed 3pool admission change without a funded mainnet probe, we can use an ICP canister snapshot to obtain the exact installed Wasm for local testing. No snapshot has been taken and no canister has been stopped under this proposal.

The [ICP snapshot guide](https://docs.internetcomputer.org/guides/canister-management/snapshots/) requires the canister to be stopped before snapshot creation. A stop rejects new calls and waits for outstanding responses; this is a short but user-visible production outage, so it needs an agreed maintenance window. The downloaded snapshot contains the Wasm and private canister state. Keep it in a protected local directory, never commit or upload it, and do not restore or delete a snapshot as part of evidence capture.

Before the window, verify the controller identity, Running status, module hash, cycles, memory, local disk, and current snapshot count. Privately export pool totals, depositor positions, event count, pending refunds, interest forwards, and chain-absorb records; check the pool guard/automation status and reconcile ledger balances where supported. If an unresolved obligation or active callback appears, postpone. Read-only checks taken on 2026-10-08 found no pending refunds, interest forwards, or chain absorbs, and a healthy pool guard; these must be repeated immediately before any stop.

During the window, stop only the Stability Pool and wait for confirmed `Stopped` status. If stopping fails or remains in progress, do not create a snapshot. After a successful stop, create one snapshot, record its ID, and restart the canister immediately. Verify `Running`, unchanged module hash/controllers, and post-start pool/position/obligation state. Download the snapshot only after service is restored, verify its metadata and Wasm hash, and use that Wasm in local PocketIC tests with the candidate 3pool code. Preserve the snapshot as a rollback aid until the release decision is closed. A separate restore, deletion, upgrade, or activation requires its own evidence and decision.

This proposal does not establish a safe cap install by itself. The local test must cover an admission rejection after Stability Pool has received funds and verify the refund and recovery path. If the snapshot cannot be taken safely, keep the cap install held while a separately reviewed, state-preserving Stability Pool upgrade is prepared.
