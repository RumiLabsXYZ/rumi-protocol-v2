## What the implementation changes

- `reserve.rs` adds a serde-compatible optional reserve state, disabled until
  explicitly configured and enabled. It keeps cumulative allocated and settled
  totals and record/generation/payment-bound allocation tombstones. Caps, lifetime
  budget, protected wallet floor and a bounded 1024-entry history all fail closed.
- `process.rs` checks a conservative pool quote, withdrawal fee, backend payment
  fee and reserve availability **before claiming collateral**. An uneconomic
  vault is left unlocked for ordinary manual/Stability Pool handling. This is
  an admission estimate; actual post-swap receipts and balances are checked again.
- After a measured swap, only the exact shortfall may be allocated from the
  reserve. Claim removal, reserve allocation and immutable payment preparation
  happen in the same BotState mutation and are saved before dispatch. The
  existing proof-bound payment and treasury journals perform delivery/recovery.
- Reserve-backed definitive-no-effect retries retain the original timestamp,
  memo, amount, fee and budget allocation. Fee changes, an expired retry window
  or an unavailable protected balance stay held. Ambiguous replies never
  authorize a new tuple or second allocation. Settlement refusal stops before
  treasury construction, preventing duplicate residual delivery.
- `process/recovery202.rs` handles only Vault 202 / generation 3 / record 231. It verifies
  native ICP claim block 40431390, native pool-input block 40431407 and ckUSDC
  pool-output block 815252; all amounts, accounts, fees, memos and saved claim/
  record fields are pinned. The first payment requires the exact frozen wallet
  baseline plus output. Repeated calls can only continue the saved tuple or
  observe the completed tombstone, never create a second payment.
- New admin methods keep the existing admin/anonymous and ProcessingGuard
  checks. Existing158 recovery evidence/tombstone and unrelated liabilities are
  retained. The shared native-block reader is extracted without changing the
  deployed Vault 158 input-receipt predicate. Existing ordinary input/top-up fee sizing,
  fee accounting and treasury residual rules remain source-equivalent to 2edd5e01.
